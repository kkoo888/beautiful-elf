# MySQL P3C 规约（阿里巴巴 Java 开发手册 - 黄山版）

> 来源：[alibaba/p3c](https://github.com/alibaba/p3c)《Java开发手册（黄山版）》MySQL 数据库章节

## 一、建表规约

### 1.1 库名规范

| 级别 | 规则 | 说明 |
|------|------|------|
| 推荐 | 库名与应用名称尽量一致 | 便于识别和管理 |

### 1.2 表名规范

| 级别 | 规则 | 正例 | 反例 |
|------|------|------|------|
| 强制 | 表名必须使用小写字母或数字 | `getter_admin` | `GetterAdmin` |
| 强制 | 禁止数字开头 | `task_config` | `3_task` |
| 强制 | 禁止两个下划线中间只出现数字 | `level3_name` | `level_3_name` |
| 强制 | 表名不使用复数名词 | `user` | `users` |
| 强制 | 禁用保留字 | — | `desc`, `range`, `match`, `delayed` |
| 推荐 | 命名格式：`业务名称_表的作用` | `tiger_task`, `tiger_reader`, `mpp_config` | — |

### 1.3 字段规范

#### 1.3.1 布尔型字段

| 级别 | 规则 | 正例 | 反例 |
|------|------|------|------|
| 强制 | 命名必须 `is_xxx` | `is_deleted` | `deleted` |
| 强制 | 数据类型 `unsigned tinyint` | `tinyint unsigned` | `int` |
| 强制 | 1 表示是，0 表示否 | — | — |
| 强制 | 任何非负数字段必须 `unsigned` | — | — |

> ⚠️ **POJO 类中的布尔变量不要加 `is` 前缀**，需在 resultMap 中映射 `is_xxx` → `xxx`，防止序列化失败。

#### 1.3.2 小数类型

| 级别 | 规则 | 正例 | 反例 |
|------|------|------|------|
| 强制 | 小数类型用 `decimal` | `decimal(10,2)` | `float`, `double` |

> 说明：float/double 存在精度损失，可能导致比较结果不正确。超出 decimal 范围时，拆分整数和小数分开存储。

#### 1.3.3 字符串类型

| 级别 | 规则 | 正例 | 反例 |
|------|------|------|------|
| 强制 | 长度几乎相等用 `char` | `char(11)` 存手机号 | `varchar(11)` |
| 强制 | `varchar` 长度不超过 5000 | — | `varchar(10000)` |
| 强制 | 超过 5000 用 `text`，独立成表 | 主键关联 | — |

#### 1.3.4 必备字段

| 级别 | 规则 |
|------|------|
| 强制 | 表必备三字段：`id`, `gmt_create`, `gmt_modified` |
| 强制 | `id` 为主键，类型 `unsigned bigint`，单表自增步长 1 |
| 强制 | `gmt_create`, `gmt_modified` 类型为 `datetime` |

> 💡 可用 `create_time`, `update_time` 替代 `gmt_create`, `gmt_modified`。

#### 1.3.5 其他字段规范

| 级别 | 规则 |
|------|------|
| 推荐 | 字段含义变更时及时更新注释 |
| 推荐 | 允许适当冗余提高查询性能（非频繁修改、非超长字段） |
| 推荐 | 单表超 500 万行或 2GB 再考虑分库分表 |
| 参考 | 合理选择存储长度（见下表） |

**存储长度参考：**

| 对象 | 年龄区间 | 类型 | 表示范围 |
|------|----------|------|----------|
| 人 | 150 岁内 | `unsigned tinyint` | 0~255 |
| 龟 | 数百岁 | `unsigned smallint` | 0~65535 |
| 恐龙化石 | 数千万年 | `unsigned int` | 0~约 42.9 亿 |
| 太阳 | 约 50 亿年 | `unsigned bigint` | 0~约 10^19 |

### 1.4 外键与级联

| 级别 | 规则 | 说明 |
|------|------|------|
| 强制 | 禁用外键与级联 | 一切外键概念必须在应用层解决 |

> 外键影响插入速度，级联更新是强阻塞，存在更新风暴风险。适用于单机低并发，不适合分布式高并发集群。

## 二、索引规约

### 2.1 索引命名规范

| 级别 | 规则 | 正例 |
|------|------|------|
| 强制 | 主键索引名 `pk_字段名` | `pk_user_id` |
| 强制 | 唯一索引名 `uk_字段名` | `uk_email` |
| 强制 | 普通索引名 `idx_字段名` | `idx_name` |

### 2.2 索引创建规范

| 级别 | 规则 | 说明 |
|------|------|------|
| 强制 | 业务上具有唯一特性的字段必须建唯一索引 | 即使应用层做了校验，没有唯一索引必然产生脏数据 |
| 强制 | 超过三个表禁止 join | 需要 join 的字段数据类型必须一致 |
| 强制 | varchar 字段索引必须指定长度 | 根据实际区分度决定，一般长度 20 区分度可达 90%+ |
| 强制 | 禁止左模糊或全模糊搜索 | 需要请走搜索引擎 |
| 推荐 | order by 场景利用索引有序性 | `idx_a_b_c` 配合 `WHERE a=? AND b=? ORDER BY c` |
| 推荐 | 利用覆盖索引避免回表 | explain 结果 extra 列出现 `Using index` |
| 推荐 | 延迟关联/子查询优化深分页 | `SELECT a.* FROM 表1 a, (SELECT id FROM 表1 WHERE 条件 LIMIT 100000,20) b WHERE a.id=b.id` |
| 推荐 | SQL 性能至少达到 range 级别 | consts > ref > range |
| 推荐 | 组合索引区分度最高的放最左边 | 等号条件列前置 |
| 推荐 | 防止字段类型不同造成隐式转换 | 导致索引失效 |
| 参考 | 避免索引三大误区 | ① 宁滥勿缺 ② 宁缺勿滥 ③ 抵制唯一索引 |

## 三、SQL 语句规约

### 3.1 聚合函数

| 级别 | 规则 | 说明 |
|------|------|------|
| 强制 | 使用 `count(*)` 统计行数 | 禁止用 `count(列名)` 或 `count(常量)` 替代，`count(*)` 是 SQL92 标准语法，与 NULL 无关 |
| 强制 | `count(*)` 与 `count(1)` 等效 | `count(1)` 不检查各行数据，性能可能略高于 `count(*)`，但语义一致 |
| 强制 | `count(col)` 不统计 NULL 行 | 若该列全为 NULL，`count(col)` 返回 0 |
| 强制 | `count(distinct col)` 注意 NULL | 若一列全为 NULL，即使另一列不同也返回 0 |
| 强制 | `sum(col)` 注意 NPE | 全 NULL 时 sum 返回 NULL，用 `IF(ISNULL(SUM(g)),0,SUM(g))` |

### 3.2 NULL 处理

| 级别 | 规则 | 说明 |
|------|------|------|
| 强制 | 使用 `ISNULL()` 判断 NULL | NULL 与任何值直接比较都为 NULL |
| 强制 | `NULL<>NULL` 返回 NULL（非 false） | — |
| 强制 | `NULL=NULL` 返回 NULL（非 true） | — |

### 3.3 查询规范

| 级别 | 规则 | 说明 |
|------|------|------|
| 强制 | 禁止 `SELECT *` | 必须明确写出需要的字段 |
| 强制 | 分页查询 count 为 0 直接返回 | 避免执行后续分页语句 |
| 强制 | 数据订正前先 SELECT 确认 | 避免误删除/误修改 |
| 强制 | 禁用存储过程 | 难以调试和扩展，没有移植性 |
| 推荐 | in 操作控制在 1000 个元素内 | 能避免则避免 |
| 参考 | 字符存储与表示均用 utf-8 编码 | 需要存储 emoji 时用 utf8mb4，注意与 utf-8 的区别 |
| 参考 | 区分 `LENGTH()` 和 `CHARACTER_LENGTH()` | `LENGTH("轻松工作")`=12，`CHARACTER_LENGTH("轻松工作")`=4 |
| 推荐 | 不建议在开发代码中使用 TRUNCATE | 无事务且不触发 trigger，可能造成事故 |

## 四、ORM 映射规约

| 级别 | 规则 | 说明 |
|------|------|------|
| 强制 | 禁止 `SELECT *` | 明确写出字段列表 |
| 强制 | POJO 布尔属性不加 is | 数据库 `is_xxx`，POJO 用 `xxx`，resultMap 映射 |
| 强制 | 不用 resultClass 当返回参数 | 即使字段一一对应也需定义 resultMap |
| 强制 | SQL 参数用 `#{}` `#param#` | 禁止 `${}` 防止 SQL 注入 |
| 强制 | 禁用 `queryForList(String, int, int)` | 其实现是取出全部再 subList |
| 强制 | 禁止 HashMap/Hashtable 作为查询结果集 | 值类型不可控 |
| 强制 | 更新记录必须同时更新 `gmt_modified` | 为当前时间 |
| 推荐 | 不写大而全的更新接口 | 只更新有改动的字段，减少 binlog 存储 |
| 参考 | `@Transactional` 不要滥用 | 事务影响 QPS，需考虑回滚方案（缓存回滚、搜索引擎回滚、消息补偿、统计修正等） |
| 参考 | `<isEqual>` 中 compareValue 是常量 | 一般是数字，表示相等时带上此条件 |
| 参考 | `<isNotEmpty>` 表示不为空且不为 null 时执行 | `<isNotNull>` 表示不为 null 值时执行 |

## 五、速查清单 ✅

### 建表检查
- [ ] 表名小写、无复数、无保留字
- [ ] 布尔字段 `is_xxx` + `unsigned tinyint`
- [ ] 小数用 `decimal`
- [ ] 固定长度字符串用 `char`
- [ ] varchar 不超过 5000，超过用 `text` 独立成表
- [ ] 必备字段：`id`(主键), `gmt_create`, `gmt_modified`
- [ ] 禁用外键和级联

### 索引检查
- [ ] 命名：`pk_` / `uk_` / `idx_`
- [ ] 唯一字段必须建唯一索引
- [ ] varchar 索引指定长度
- [ ] 禁止左模糊/全模糊
- [ ] 组合索引区分度高的在左
- [ ] 利用覆盖索引避免回表

### SQL 检查
- [ ] 禁止 `SELECT *`
- [ ] 用 `count(*)` 统计行数
- [ ] 用 `IS NULL` / `IS NOT NULL` 或 `ISNULL()` 判断 NULL
- [ ] 分页 count=0 直接返回
- [ ] 数据订正前先 SELECT
- [ ] 参数用 `#{}` 防注入
- [ ] 禁用存储过程
- [ ] 不建议在代码中使用 TRUNCATE（无事务、不触发 trigger）
